# 전환 추적: 지금 구조의 근본 문제와 해결책

> 이 문서가 이 저장소에서 **가장 먼저 처리해야 할 항목**입니다.
> 여기가 해결되지 않으면 아래의 어떤 최적화도 근거 없는 추측이 됩니다.

## 1. 문제

현재 광고의 최종 도착지가 **네이버 스마트스토어 상품 페이지**입니다.
스마트스토어는 판매자가 상품·주문완료 페이지에 **외부 스크립트를 삽입할 수 없습니다.**
즉 Google Ads 전환 태그(`gtag.js`)나 전환 링커를 심을 방법이 없습니다.

여기서 따라오는 결과:

| 항목 | 현재 상태 |
| --- | --- |
| 실제 구매를 Google Ads 전환으로 기록 | ❌ 불가 |
| 구매 금액을 전환 가치로 전달 | ❌ 불가 |
| GCLID 기반 광고 귀속 | ❌ 불가 (스토어가 파라미터를 받아 저장하지 못함) |
| 타겟 CPA / 타겟 ROAS 스마트 입찰 | ⚠️ 근거 데이터가 없어 사실상 작동 불가 |

그래서 Google Ads 화면에 지금 보이는 **전환수·전환 가치는 실제 매출이 아닐 가능성이
매우 높습니다.** 계정에서 다음 중 무엇인지부터 확인하세요.

- 전환 액션이 **'페이지 조회'나 '클릭'** 으로 잡혀 있는가 → 매출과 무관한 숫자
- 전환 액션에 **고정 가치(예: 1회당 9만 원)** 가 임의로 지정돼 있는가 → 추정치
- 전환 액션이 아예 없는데 '전환수'가 보이는가 → 자동 생성된 전환일 수 있음

**확인 경로:** Google Ads → 목표 → 전환 → 요약 → 각 전환 액션의
*소스 / 카테고리 / 값 / 집계 방식* 을 캡처해 두세요.

## 2. 해결책 (권장 순서)

### A안 — 자사 랜딩 경유 (권장)

```
Google Ads 광고
      │
      ▼
자사 랜딩페이지          ← 여기에 Google 태그 + 전환 태그 설치 (설치 가능)
 (hellobell.shop / helloclick.kr)
      │
      ├─ [주 전환] 견적 문의 폼 제출 / 전화 클릭 / 카카오 채널 클릭
      └─ [보조 전환] '스마트스토어에서 구매하기' 아웃바운드 클릭
```

- 비상벨은 관공서·학교·병원 **대량 구매 문의**가 매출의 큰 축입니다.
  이 문의를 주 전환으로 잡으면 스마트스토어 없이도 정확히 측정됩니다.
- 스마트스토어 판매는 랜딩의 아웃바운드 클릭을 **보조 전환(가치 낮게)** 으로 두고,
  실제 주문 수는 스마트스토어 통계와 대조해 보정합니다.
- Cafe24 기반 자사몰(hellobell.shop)이라면 스크립트 설치가 가능하므로
  **실제 구매 전환과 매출액**까지 그대로 측정됩니다. 가능하면 광고 도착지를
  스마트스토어가 아니라 자사몰로 바꾸는 것이 가장 깔끔합니다.

**설치 항목 체크리스트**

- [ ] Google 태그(gtag.js) 전 페이지 삽입
- [ ] GA4 속성 연결 + Google Ads 계정 연결
- [ ] 전환 액션 생성: `견적문의_폼제출` (주), `전화클릭` (주), `카톡채널클릭` (주),
      `스토어이동클릭` (보조), `구매완료` (자사몰이 있을 때, 값=주문금액)
- [ ] '주요 전환'으로 지정할 액션 선택 → 입찰 최적화 대상이 됨
- [ ] 강화된 전환(Enhanced Conversions) 설정 — 폼의 이메일/전화번호 해시 전달
- [ ] 전환 추적 테스트: 광고 미리보기로 실제 폼 제출 후 계정에 기록되는지 확인

### B안 — 스마트스토어를 유지해야 한다면 (차선)

전환을 정확히 귀속시킬 방법은 없습니다. 대신 **근사치**를 만듭니다.

1. 광고 최종 URL에 유입 파라미터를 붙입니다.
   예: `...?NaPm=...` 대신 스마트스토어가 인식하는 채널 파라미터를 사용하고,
   구글 광고를 별도 채널로 구분되게 설정합니다.
2. 스마트스토어 관리자 → 통계 → 마케팅분석에서 해당 채널의 **주문 수·결제 금액**을
   주 단위로 확인합니다.
3. 그 숫자를 `data/manual_orders.csv` 같은 파일로 기록해 두고, 광고비와 나란히
   비교합니다. (Google Ads 계정 안의 전환 숫자는 신뢰하지 않습니다.)

⚠️ 이 방식은 유입 채널 구분 정확도가 완전하지 않고, 스마트 입찰에 데이터를
넘길 수 없습니다. **A안으로 가는 중간 단계로만** 쓰세요.

### C안 — 오프라인 전환 가져오기 (B2B 비상벨에 특히 유효)

1. 자사 랜딩에서 URL의 `gclid` 값을 읽어 문의 폼의 숨김 필드에 저장합니다.
2. 문의가 실제 계약/납품으로 이어지면, `gclid + 전환시각 + 매출액` 을
   Google Ads → 목표 → 전환 → 업로드 로 올립니다.
3. 그러면 "어떤 키워드가 **실제 매출**을 만들었는지" 까지 연결됩니다.
   관공서·학교 납품처럼 결제까지 시차가 긴 거래에 맞는 방식입니다.

## 3. 지금 당장 할 수 있는 최소 조치

자사 랜딩 작업에 시간이 걸린다면, 그 사이에도 아래는 바로 됩니다.

- **전화 전환**: 광고 확장에 전화번호를 넣고 '광고에서 전화 클릭'을 전환으로 설정.
  랜딩 없이도 측정되며, 비상벨 문의는 상당수가 전화로 들어옵니다.
- **전환 가치 임시 지정**: 문의 1건의 기대 매출을 계산해 고정 가치를 넣습니다.
  (예: 문의 10건 중 3건 성사 × 평균 90,000원 = 문의 1건당 27,000원)
  근사치라도 있어야 캠페인 간 비교가 가능합니다.
- **캠페인별 URL 태깅**: 최종 URL 접미어에
  `utm_source=google&utm_medium=cpc&utm_campaign={campaignid}&utm_term={keyword}`
  를 넣어 두면, 나중에 어떤 방식으로든 분석할 때 원천 데이터가 남습니다.
