# 지속 개선 루틴

"세팅하고 끝"이 아니라 반복해서 돌리는 사이클을 정의합니다.
각 항목 옆의 명령을 그대로 실행하면 됩니다.

## 매주 (15분) — 월요일

```bash
python3 scripts/fetch_ads.py --days 7    # API 연동 시. 미연동이면 CSV 수동 다운로드
python3 scripts/analyze.py
python3 scripts/search_terms.py
```

- [ ] `reports/search_terms_*.md` 1·2번 표 확인 → 제외할 검색어 확정
- [ ] `campaigns/generated/negatives_to_add.csv` 를 Editor 로 업로드
- [ ] 3번 표(전환 발생 검색어)에서 목표 CPA 이내인 것 → **정확일치로 승격**
- [ ] 전환 0 · 클릭 20회 이상 키워드 → 입찰 30% 하향 (그래도 2주 뒤 0이면 일시중지)
- [ ] 예산 부족으로 노출을 잃는 캠페인이 있는지 확인
      (검색 손실 노출 점유율(예산) > 10% → 성과가 좋으면 증액)

## 격주 (30분)

- [ ] RSA **애셋 실적** 확인: Google Ads → 광고 → RSA → '애셋 세부정보'
      - `낮음` 등급 헤드라인을 새 문안으로 교체 (한 번에 2~3개씩만)
      - `campaigns/ads.yaml` 도 함께 수정해서 저장소와 실제 계정을 일치시킬 것
- [ ] 검색어에서 **새 광고그룹으로 뺄 주제**가 보이는지 확인
      (같은 주제 검색어가 20클릭 이상 모이면 독립 광고그룹 감)
- [ ] 기기별 성과 확인 → 모바일/PC 입찰 조정
- [ ] 시간대·요일별 성과 확인 → 관공서 문의는 평일 업무시간에 집중되는지

## 매월 (1시간)

- [ ] `python3 scripts/fetch_ads.py --days 30 && python3 scripts/analyze.py` 실행 후
      **6. 예산 재배분 권고** 를 반영
- [ ] `config/products.yaml` 의 `target_cpa` / `target_roas` 를 실제 성과 기준으로 갱신
- [ ] 입찰 전략 승급 판단
      - 캠페인 월 전환 15건 이상 → 전환수 최대화 (타겟 CPA)
      - 전환 가치가 정상 수집됨 → 전환가치 최대화 (타겟 ROAS)
- [ ] 랜딩페이지 전환율 확인. CTR은 좋은데 전환이 없다면 문제는 광고가 아니라 랜딩
- [ ] 전환 태그가 여전히 살아 있는지 확인 (Cafe24 스킨을 수정하면 스크립트가
      날아가는 일이 잦습니다 — `docs/tagging_hellobell.md` 5번 검증 목록)
- [ ] 경쟁 현황: Google Ads → 통계 → 경매 통계 보고서

## 분기 (반나절)

- [ ] 시즌성 반영
      - **헬로클릭**: 학기 시작 전(1~2월, 7~8월)과 학교 예산 집행기(10~12월)에 증액
      - **비상벨**: 관공서 발주·시설 점검 주기와 맞물리는 달이 있는지 확인
- [ ] 새 캠페인 유형 테스트 (예비 예산 10% 사용)
      - 검색이 안정되면 P-Max 또는 디맨드젠으로 확장
- [ ] `campaigns/plan.yaml` 전면 재검토 후 커밋

## 판단 기준선

`config/products.yaml` 의 `targets` 값이 자동 진단의 기준입니다.
데이터가 쌓이면 아래를 실제 값으로 바꾸세요.

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| `min_clicks_for_judgement` | 30 | 이 미만이면 "아직 판단하지 말 것" |
| `ctr_floor` | 3% | 검색 캠페인 CTR 하한선 |
| `wasted_spend_click_threshold` | 20 | 전환 0인데 이 이상 클릭 → 낭비로 표시 |
