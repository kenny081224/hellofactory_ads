## 2. B안이 더 나았던 점 — 전부 채택

### ① 2026년 4월 집중을 지적해 A안의 결론을 뒤집음 ★

A안은 "P-Max ROAS 0.638 vs 검색 0.011 — **P-Max 비중 상향 검토**"라고 했습니다.
B안이 지적한 88.7% 집중을 근거로 다시 계산하니 결과가 달라집니다.

| 캠페인 | 전체 ROAS | **4월 제외 ROAS** | 전체 CPA | 4월 제외 CPA |
| --- | ---: | ---: | ---: | ---: |
| 비상벨 검색어 클릭 | 0.011 | 0.011 | 138,634원 | 132,968원 |
| 비상벨 구매 광고 (P-Max) | 0.638 | **0.035** | 38,244원 | 42,963원 |

**P-Max의 ROAS 우위는 한 달 3건에 전적으로 의존합니다.**
정확한 결론은 이렇습니다 — **건수 효율(CPA)은 P-Max가 3배 낫고 신뢰할 만하지만,
가치(ROAS) 우위는 신뢰할 수 없습니다.**

→ 병합안: P-Max를 이번 출시에서 빼되, 근거를 명시하고 재개 조건을 정의.
A안의 "제외"도 B안의 "일 2,300원으로 포함"도 아닙니다. (B안 방식은 P-Max
학습에 필요한 최소 예산에 크게 못 미쳐 실질적으로 작동하지 않습니다.)

### ② 전환을 단계로 나눔 — A안의 가장 큰 구멍

A안은 `대여문의_헬로클릭` 하나로 끝냈습니다. B안은 이렇게 나눕니다.

```
문의 폼 제출 → 적격 리드 → 견적 발송 → 계약
                            ↑ CRM 오프라인 전환으로 업로드
```

리드로 먹고사는 사업에서 폼 제출을 전부 하나로 세면 **스팸과 단순 문의까지
최적화 대상**이 됩니다. B안이 맞습니다.

여기에 B안은 **`gclid`·`gbraid`·`wbraid` 를 CRM에 저장**하라고 명시했습니다.
A안은 `gclid`만, 그것도 설정서가 아니라 별도 문서에만 적어 뒀습니다.

→ 병합안 1-1, 1-2에 전환 11개(헬로벨 5 / 헬로클릭 6)와 클릭 ID 저장을 반영.

### ③ 광고 표현 검증 — A안 문안에 실제 위험이 있었음 ★

B안의 지적: "낙상 자동 감지 기능이 없다면 '자동 감지' 표현 금지",
"119 자동 연결 확인 안 되면 금지", "생명·안전 보장하는 단정 표현 금지".

**A안 v1에 실제로 문제 소지가 있었습니다.**

| A안 v1 | 문제 |
| --- | --- |
| 헤드라인 `낙상 사고 즉시 알림` | 제품은 **버튼을 눌러야** 알립니다. 자동 감지로 읽힘 |
| 키워드 `"낙상 감지 호출벨"` | 자동 감지를 찾는 검색. 랜딩 불일치 + 정책 소지 |

→ 병합안: 해당 문안·키워드 삭제. `버튼 누르면 보호자에게`처럼 동작을 명시하는
표현으로 교체. **생성 스크립트에 금지어 자동 검사를 넣어** 재발을 막았습니다.

```python
BANNED = ["자동 감지", "자동감지", "119", "생명을", "안전을 보장", "100%", ...]
```

### ④ 기기·일정 입찰 조정 보류 — A안의 근거가 오염된 데이터

A안은 모바일 -30%, 토요일 -50%, 08~09시 -40%를 첫날부터 적용하려 했습니다.
근거는 기기·시간대 리포트였는데, **그 리포트는 3년 전체 기간이고 1년차가
비용의 70%·전환의 99.5%를 차지합니다.** 새 구조에 그대로 적용할 수 없습니다.

B안의 "첫 30일 조정 없음"이 맞습니다.

→ 병합안: 기기·일정 **입찰 조정은 30일 보류**. 다만 **광고 노출 시간대 제한은
유지**합니다(전화 상담이 주 전환인데 야간에는 응대가 안 되므로).
이건 과거 성과가 아니라 운영 조건에 근거한 것이라 별개입니다.

### ⑤ 헬로벨 개인 / 시설 분리, 헬로클릭 렌탈 / 구매 분리

A안은 `공공·돌봄` / `시설·가정`으로 나눠 **가정(B2C)을 시설 캠페인에 섞었습니다.**

### ⑥ 학교 제외하되 '교육' 단어는 남기기

B안: "기업교육과 사내교육은 목표 고객이므로 `교육` 전체를 제외하면 안 된다."

## 3. A안이 더 나았던 점 — 유지

### ② 매치타입을 키워드별로 지정

B안: "각 키워드는 일치검색과 구문검색으로 생성한다."

**모든 키워드를 두 매치타입으로 만들면 안 됩니다.** `[노인 안심벨]`과
`"노인 안심벨"`이 같은 광고그룹에 있으면 같은 검색어를 두고 서로 경쟁하고,
리포트가 쪼개져 판단이 어려워집니다. 구문일치는 확장 여지가 필요한 키워드에만
씁니다.

→ 병합안: 키워드마다 정확 또는 구문 중 하나로 지정 (4장).

### ③ 광의어는 '정확일치 제외'로

B안: "명확한 비구매 주제는 개별 일치 제외보다 구문 제외를 우선한다."

투표 주제에서는 이게 위험합니다.

```
[온라인 투표]  정확 제외 → '온라인 투표'            차단 ✅
                        → '온라인 투표 시스템 대여'  노출 ✅ ← 팔아야 할 검색어
"온라인 투표"  구문 제외 → 둘 다 차단 ❌
```

다만 B안의 제외 목록에는 광의 단독어가 들어있지 않아 **실제 충돌은
없었습니다.** 원칙 표현이 부정확했을 뿐입니다.

→ 병합안: 광의 단독어 8개는 정확일치 제외, 나머지는 구문 제외 (5-3).

### ④ 캠페인 수

B안은 일 10,000원에 캠페인 7개 = **캠페인당 평균 1,430원**입니다.
CPC 842원이면 캠페인당 하루 1.7클릭이라 어느 캠페인도 학습이 안 됩니다.
특히 P-Max 일 2,300원은 실질적으로 작동하지 않습니다.

→ 병합안: 5개 캠페인, 최소 590원(브랜드)~2,760원(주력).
B안 스스로도 축소안에서 "예산이 작으면 캠페인을 세분화하지 말고 광고그룹으로
분리한다"고 했는데, 본안이 그 원칙을 지키지 않았습니다.

### ⑤ 재현 가능한 생성 구조

병합안은 `campaigns/spec/*.yaml` → `docs/campaign_setup_spec.md` 로
자동 생성되고, 생성할 때마다 아래가 검사됩니다.

- 헤드라인 30자 / 설명 90자 (전각 2, 반각 1)

문안을 고칠 때 사람이 글자를 세지 않아도 됩니다.

## 5. 양쪽 다 놓친 것

### ① 키워드 검색량을 확인하지 않았습니다 ★

병합안의 99개 키워드 중 상당수가 **월 검색량이 0에 가까울 수 있습니다.**
특히 신규 세그먼트가 그렇습니다.

```
'응급안전안심서비스'  '재가 어르신 응급벨'  '돌봄 대상자 응급벨'
'청중 평가단 시스템'  '현장 만족도 조사 장비'  '연수원 청중 응답'
```

두 분석 모두 제품 자료와 과거 실적에서 키워드를 도출했을 뿐,
**Google 키워드 플래너로 실제 검색량을 확인하지 않았습니다.**

→ **출시 전 필수 작업**: 키워드 플래너에 99개를 넣고 월간 검색량을 확인해
   - 검색량 0인 키워드는 등록하되 입찰을 낮게 (노출 안 되면 비용도 없음)
   - 검색량이 큰데 빠진 키워드가 있으면 추가
   - 광고그룹별로 검색량 합계가 너무 작으면 그룹을 합칩니다

이건 설정 전에 30분이면 끝나고, 안 하면 광고그룹 절반이 노출 0으로
4주를 흘려보낼 수 있습니다.

### ② 계절성이 예산 계획에 없습니다

헬로클릭 렌탈은 행사 시즌(3~6월, 9~11월)과 아파트 정기총회(11~12월)에
수요가 몰립니다. 두 안 모두 "분기 점검" 수준으로만 언급했습니다.

→ 병합안 운영 규칙에 반영했지만, 실제로는 **월별 예산을 평탄하게 두지 말고
성수기에 배분을 옮기는 계획**이 필요합니다. 첫 3개월 데이터를 본 뒤 결정하세요.
